## 先看请求，再判断前后端

页面出问题，第一反应往往是「后端挂了」。但「数据为空」也可能只是前端 API 路径写错。

正确的顺序是：

1. 打开开发者工具，切到 Network，刷新页面；
2. 看请求的 URL、方法、状态码、请求参数和响应；
3. 4xx 先查前端，5xx 再查后端；
4. 前端报错看 Console，后端报错看日志；
5. 把完整报错和复现步骤发给 AI，一次只改一个地方。

### 状态码是最快的线索

- 200 成功；201 已创建；204 无内容；
- 400 参数有误；401 未登录；403 无权限；404 地址不存在；405 方法不对；
- 500 服务器内部错误；502 网关错误；503 服务不可用；504 网关超时。

把状态码看对，能省掉一半的排查时间。

### AI 改不动时，及时止损

同一个 Bug 让 AI 改了三轮还不行，继续对话往往只会越改越乱。更有效的做法是：

- Git 回退到修改前；
- 新开对话，补充更多上下文；
- 换一种描述，甚至换一个模型；
- 范围不确定时二分排查，注释掉一半代码看问题还在不在；
- 端口占用、缓存、进程卡死，先重启。

修好之后让 AI 生成单元测试和接口测试，避免下次改动又把它弄坏。

## 部署：三种方式

- 网站托管平台：Cloudflare Pages、Vercel、Netlify、GitHub Pages。导入仓库，自动构建，分配域名，适合静态站和前端项目；
- 容器托管平台：微信云托管、Railway、腾讯云 / 阿里云容器服务。镜像跑在平台上，前后端都能部署；
- 云服务器：灵活度最高，自己装环境、跑 Docker、配反向代理。

演示时踩到的两个小问题：平台自动识别框架不一定准，构建命令和输出目录要自己核对；Vercel 注册后的安全设置可以选 `Skip securing my account` 跳过。

## 项目开发流程：五步与三份文档

1. 需求研究：明确要解决什么问题，调研同类产品和开源项目；
2. PRD：写清做什么、不做什么，MVP 与后续版本分开；
3. TECH_DESIGN：技术栈、项目结构、数据模型、关键技术点；
4. AGENTS.md：开发规范、测试要求、代码风格、注意事项；
5. 开发与部署：先生成框架，再逐个实现核心功能，最后打磨细节。

复杂项目不要指望一次生成。三步走：能跑的框架 → 核心功能逐个跑通 → 优化细节。每完成一个功能就测试、提交。

> PRD 和技术文档生成后必须逐条读。老师演示的电子书阅读器，AI 就把桌面应用写成了纯前端网页架构；文档阶段不改，后面整个项目都会返工。
